# pi-career-skills 教案 — 五层递进式拆解一个生产级多 Agent 运行时

> 来源：`packages/pi-career-skills/src` + `packages/pi-agent-core/src` 真实源码。当前实现是一个**求职多 Agent 评测运行时**：四个技能（job-discovery / job-matching / resume-tailoring / career-planning）、13 个确定性工具，以及 run 级 harness（证据库、完成门、预算、stall 检测、有界自动恢复、类型化委托契约）。文中代码行号以当前工作树为准；涉及网络抓取的示例均遵守站点条款，不绕过验证码或访问控制。
>
> 本文按 **"目标边界 → 记忆 → 行动 → 稳健 → 进化"** 五层递进式组织，从外到内、从设计到运维。每一层都严格标注代码里**有的**（带 `file:line` 证据）和**没有的**（直接写明"没有"，绝不虚构）。
>
> 五维一句话串联：**第一维定义大脑的"智商"下限，第二维提供"知识储备"，第三维赋予"手脚能力"，第四维确保"不失控"，第五维让"持续发育"。**

## 0. 架构总览（先把地图摊开）

```
用户请求（RunRequest：task + 用户信息 + seed 证据）
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ CareerRunController（可信内核，controller.py:166 run）        │
│  ├─ 预算三件套：BudgetLimits / BudgetTracker / ToolCallGuard │
│  ├─ EvidenceStore（证据库：唯一写入口 add_observation）       │
│  ├─ 完成门：RunCompletionPolicy（证据+摘要+refs 全通过才算成功）│
│  ├─ attempt 循环（失败可自动恢复，预算 1.5x → 2.0x 放宽）      │
│  ├─ EventLogger（有界事件流，可订阅）                         │
│  └─ 能力注册表 CAPABILITY_REGISTRY（4 技能元数据 + 默认子预算） │
├──────────────────────────────────────────────────────────┤
│ Supervisor Agent —— 只看到 4 个 delegate-<skill> 工具          │
│    │ 委托 delegate-job-discovery / -matching / -tailoring    │
│    │     / -planning                                        │
│    ▼                                                        │
│ 技能子代理（每次委托都是 fresh Agent，工具 10 / 1 / 1 / 1）      │
└──────────────────────────────────────────────────────────┘
```

**核心信条**（源码注释原文，[controller.py:8-9](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L8-L9)）：*"The controller is the trusted kernel: budgets, evidence, and completion are its authority — model output is never trusted directly."* —— 模型说"我完成了"不算数，**证据库里的 artifact、预算计数、完成门判定**才算数。这句信条会贯穿下面五维。

## 第一维度：目标边界与认知范式（顶层设计）

**逻辑支点**：定义"为何而建、怎么思考"。这是架构的基石。

### 1.1 场景锚定：自主执行型，但留了"向用户要证据"的出口

- **入口是一个自然语言目标**：`RunRequest(task, user_id, allowed_skills, needed_skills, budget, seed_artifacts, private_context)`（[controller.py:97-112](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L97-L112)）——用户给一句话任务（如"收集华为 AI 应用开发岗位，匹配并出简历建议"），其余全交给 agent。
- **这是自主决策型 + 单轮长任务规划**：一个 run 内部完成"发现职位 → 匹配排序 → 简历建议 → 准备计划"多技能多步骤闭环，不是副驾驶式逐轮问答。
- **但保留了"证据不足就回头问用户"的出口**：委托结果有 `NEED_USER` 态（[contracts.py:18](packages/pi-career-skills/src/pi_career_skills/agents/contracts.py#L18)），run 有 `waiting_user` 终态（完成门产出）。**自主 ≠ 无人值守**——宁可停下来要证据，也不让模型编结论。

### 1.2 认知范式选型：经典 ReAct（有）；CoT / Plan-and-Execute / Reflexion（没有）

- **ReAct：是**。pi-agent-core 的循环是教科书式 ReAct —— LLM 生成 → 抽取工具调用 → 执行工具 → 结果回填 → 再拉模型（[agent_loop.py:170-254](packages/pi-agent-core/src/pi_agent_core/agent_loop.py#L170-L254)）。Supervisor 和每个技能子代理都是同一个循环（factory 用 `Agent(...)` 构建，[factory.py:87-101](packages/pi-career-skills/src/pi_career_skills/agents/factory.py#L87-L101)）。思考与行动交错，这是多 Agent 编排的"通用神经回路"。
- **Plan-and-Execute：没有作为认知范式**。注意区分：`career-planning` 是一个**技能**，产出的是"求职准备计划"这一业务交付物（artifact），它**不是**运行时把任务先拆成计划再执行的认知机制。Supervisor 不先规划再执行，而是边想边调工具。
- **Reflexion / 显式 CoT 提示：没有**。循环里没有自我反思阶段；也没有为各 agent 配置显式推理级别（`AgentState` 只设了 `system_prompt/model/tools`，未设 `thinking_level`，[factory.py:89-92](packages/pi-career-skills/src/pi_career_skills/agents/factory.py#L89-L92)）。
- **认知配置的一个差异化能力：不同 Agent 可用不同模型**。`controller._model_for(agent_name)` 按 agent 名解析模型，缺省回落 run 模型（[controller.py:158-160](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L158-L160)）——"哪只手用哪块肌肉"，可给 discovery 配强模型、给 matching 配便宜模型。

### 1.3 范式之外的加固：Trusted Kernel —— 这个项目真正有含金量的地方

它不是靠"更聪明的推理范式"取胜，而是靠 **"模型输出永不直接信任"** 这一层加固（三不信）：

1. **工具调用永不抛异常**：所有工具统一返回 `ToolObservation` 信封（status: succeeded/failed/blocked + error_code + 脱敏 error_message），执行链"输入校验 → handler → 输出校验"任何一步出错都转成 observation，绝不 raise（[tool_adapter.py:115-160](packages/pi-career-skills/src/pi_career_skills/tool_adapter.py#L115-L160)、[contracts.py:15-31](packages/pi-career-skills/src/pi_career_skills/contracts.py#L15-L31)）。
2. **双通道执行**：同一条业务逻辑两个入口 —— `invoke_tool`（模型用，强制技能隔离）+ `invoke_tool_sync`（可信内核用，无隔离）。模型被最小权限约束，内核完全信任自己（[tool_adapter.py:193](packages/pi-career-skills/src/pi_career_skills/tool_adapter.py#L193)）。
3. **模型拿不到完整上下文**：`AgentToolResult.content` 只放有界 JSON，完整 observation 放 `details`（模型不可见，[tool_adapter.py:237-260](packages/pi-career-skills/src/pi_career_skills/tool_adapter.py#L237-L260)）。

**面试点**：认知范式（ReAct）是标配、不值钱；**"模型不可信 → 用确定性内核兜底"**才是生产级 Agent 的分水岭。这一层决定了你讲架构时的高度。

## 第二维度：感知与记忆体系（数据上下文）

**逻辑支点**：管理"短期工作记忆"与"长期生命记忆"。

### 2.1 多模态感知层：**没有**

输入是纯文本：`task` 字符串 + `private_context` 用户信息 + `seed_artifacts` 结构化证据（[controller.py:97-112](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L97-L112)）。网页抓取只取文本/HTML。没有图像、音频、日志流处理。**如实写：本项目无多模态感知。**

### 2.2 短期记忆（上下文窗口）：没有压缩，靠三招防爆

- **没有滑动窗口 / 摘要压缩 / 重要 token 保留**：整条 transcript 一直 append 进 `context.messages`，直到预算停止（[agent_loop.py:184-219](packages/pi-agent-core/src/pi_agent_core/agent_loop.py#L184-L219)）。**没有 compaction**——pi-agent-core 的 harness 明明实现了会话树 + compaction（摘要 + 保留尾巴，[session.py:313-326](packages/pi-agent-core/src/pi_agent_core/harness/session.py#L313-L326)、[session.py:385-408](packages/pi-agent-core/src/pi_agent_core/harness/session.py#L385-L408)），但 pi-career-skills **没有使用它**（grep 无命中）。**如实写：本项目不做上下文压缩。**
- 那怎么防上下文爆掉？三招，都是"管住输入"而不是"压缩历史"：
  1. **有界投影**：子代理看到的永远是私有上下文的**有界 live-first 元数据**（证据 24KB / 候选 32KB / 最多 12 条候选 / 8 个别名，`RuntimeContextProjection`，[context_projection.py:40](packages/pi-career-skills/src/pi_career_skills/runtime/context_projection.py#L40)）。
  2. **工具输出有界化**：`bound_content` 顶多 40 个顶层字段 / 字符串 12000 字符 / 列表 20 项 / 嵌套字符串 1200 字符（[tool_adapter.py:45-71](packages/pi-career-skills/src/pi_career_skills/tool_adapter.py#L45-L71)）——跑飞的工具输出永远撑不爆上下文。
  3. **每次委托都是 fresh Agent**：消息永不跨委托复用（[factory.py:5-7](packages/pi-career-skills/src/pi_career_skills/agents/factory.py#L5-L7) 注释原文）——**每换一个技能就换一本"新作业本"**，从根本上杜绝跨技能上下文污染。

### 2.3 长期记忆（跨代理共享）：结构化证据库，不是向量库

- **有的**：`EvidenceStore` 是 run 内唯一的"长期档案柜"——跨代理共享的黑板书架，唯一写入口 `add_observation`（[evidence.py:314](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L314)）。上游技能产出的 artifact 在这里沉淀，下游技能通过引用句柄读取，不重不丢。
- **没有的**：**没有向量库 / 知识图谱**；EvidenceStore 仍是 per-run 内存对象，用户画像靠调用方每次经 `private_context` 传入，不持久化。网络层新增的是**同一服务进程内的公开页面缓存**，只用于避免重复抓取，不是用户记忆，也不承担语义召回。**如实写：这是"黑板书架"式记忆，不是 RAG 记忆。**
- 类型即记忆结构：job_discovery 产出 `public_job_page` / `structured_job_details`，matching 产出 `job_matching_report`，tailoring 产出 `resume_tailoring_brief`，planning 产出 `career_preparation_plan`。

### 2.4 记忆的质检：进档案柜的每一份证据都要过"质检员"

`add_observation` 三道闸（[evidence.py:314-376](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L314-L376)）+ 每类 artifact 一个质量门 `_is_quality_job_bearing`（[evidence.py:241-249](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L241-L249)）：

| 证据类型 | 合格标准（否则不入库） |
|---|---|
| public_job_page | `content.quality == "jd_complete"`，列表页/JS 壳/空页不算 |
| structured_job_details | ≥1 个 candidate 标题是真实职位名（不在导航黑名单里，[evidence.py:90-112](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L90-L112)）+ 职责/要求正文 ≥20 字符 |
| job_matching_report | matches 非空，或空 matches 但带 `no_candidate_satisfied_constraints` + `evaluated_candidate_count`（证明真的跑过） |
| resume_tailoring_brief | 带 `target_artifact_id` + `source_url` + 非空 `safe_actions` |
| career_preparation_plan | 带 `target_artifact_id` + 非空 `action_items`（/ `plan_items` / `actions`，[completion.py:200-210](packages/pi-career-skills/src/pi_career_skills/runtime/completion.py#L200-L210)） |

防注入与防膨胀：artifact_id 由 store 生成、模型不能指定（[evidence.py:507-512](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L507-L512)）；content_hash 锚定（canonical JSON sha256，[evidence.py:133-135](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L133-L135)）；`(type, source_url, hash)` 三键去重（[evidence.py:503-506](packages/pi-career-skills/src/pi_career_skills/runtime/evidence.py#L503-L506)）。

### 2.5 实战案例：记忆里的证据必须带"质量章"（真实修过的 bug）

本仓库真实发生并修复：`test_eval_chain.py::test_two_link_chain_inherits` 失败——环节 2 返回 `waiting_user / completion_evidence_unavailable`，但 artifacts 看着完整。

**因果链**：chain 构造 seed 时显式设 `quality="jd_complete"` → 旧版 `_seed_artifact` 构造 observation 时**丢掉了 quality 字段** → 质量门 `_quality_for` 拿到 "unknown" → 该 artifact 不在 job-bearing 集合 → 完成门 refs 解析（ANY 语义）找不到可解析 ref → 环节 2 误判失败。修复后统一走 [context_projection.py:71](packages/pi-career-skills/src/pi_career_skills/runtime/context_projection.py#L71) 的 `seed_artifact`，质量标签走完整条管线。

**面试点（教训）**：*"证据的质量标签是管线资产，任何一环丢弃它，都会让'本应完成'变成'未完成'。"* 记忆系统不只是"存什么"，更是"存的东西带不带可信度元数据"。

## 第三维度：工具生态与动作执行（肢体延展）

**逻辑支点**：解决"如何连接世界"。工具调用的鲁棒性决定项目成败。

### 3.1 工具抽象标准：统一信封 + 双向校验 + 有界化

- **统一 schema**：所有 13 个工具返回同一 `ToolObservation` 信封，输入/输出都是 pydantic model，模型输入先过 `input_model.model_validate`，handler 结果再过 `output_model.model_validate`（[tool_adapter.py:115-160](packages/pi-career-skills/src/pi_career_skills/tool_adapter.py#L115-L160)）——模型永远传不进未验证参数，也永远拿不到未验证输出。
- **技能隔离再验**：`invoke_tool` 强制 `skill_name` 匹配（supervisor 调业务工具直接 `tool_skill_forbidden`，[tool_adapter.py:289-298](packages/pi-career-skills/src/pi_career_skills/tool_adapter.py#L289-L298)）——注册表白名单是第一道门，执行期再验是第二道（防御纵深）。

### 3.2 超时 / 重试 / 降级：**没有统一工具层**，但每一层都有各自的兜底

- **如实写：工具执行层没有统一超时/重试包装**（agent 循环 `_execute_single` 没有 `asyncio.wait_for`，[agent_loop.py:458-575](packages/pi-agent-core/src/pi_agent_core/agent_loop.py#L458-L575)）。
- 实际的超时/重试是**分层的**：
  - **网络工具自带**：`page_fetch` 20s 超时 + 1 次传输层重试（安全拒绝不重试，[page_fetch.py:207-224](packages/pi-career-skills/src/pi_career_skills/network/page_fetch.py#L207-L224)）；`career_sheets` 30s + 1 次有界重试（[career_sheets.py:80-89](packages/pi-career-skills/src/pi_career_skills/network/career_sheets.py#L80-L89)）；`public_search` 20s；playwright 渲染 60s 硬顶（[playwright_worker.py:49](packages/pi-career-skills/src/pi_career_skills/network/playwright_worker.py#L49)）。
  - **run 级 wall-clock 预算**兜底一切：`should_stop_after_turn` 检查墙钟，超了就提前终止（[agent_hooks.py:114-118](packages/pi-career-skills/src/pi_career_skills/runtime/agent_hooks.py#L114-L118)）。
  - **确定性降级**：关键交付物由代码兜底——需要 matching 但模型一直没产出报告时，finalize 前**确定性调用一次** `match-observed-jobs`（走内核路径，[completion.py:334-403](packages/pi-career-skills/src/pi_career_skills/runtime/completion.py#L334-L403)）。**成败不全押在模型行为上。**

### 3.2.1 公开网页访问治理：降低反爬概率，而不是绕过风控

- **请求治理器**（[`network/request_governor.py`](packages/pi-career-skills/src/pi_career_skills/network/request_governor.py)）按 canonical URL 去重，并在同一服务进程内缓存成功页面；默认缓存 6 小时。
- 生产控制器启用同域请求间隔（默认 2.5 秒）、批量抓取串行化、站点冷却熔断（默认 30 分钟）。触发 `anti_bot_challenge` / `access_denied` 后跳过同站点兄弟 URL，不做无状态重试。
- 搜索预算保持有界（当前评测/链路为 2 路）；来源优先级是招聘台账、企业/高校官方页面，再到公开搜索和商业聚合站。拿到足量 JD 后立即停止。
- **明确没有**代理轮换、验证码破解、登录态伪造、指纹隐身或并发抢抓。这是访问节制与证据复用，不是对抗站点安全机制。

### 3.3 路由与编排：模型选技能、内核验门槛（混合路由）

- **意图路由**：不是"简单 query 直调 API vs 复杂 task 走 DAG"。实际是——Supervisor 是自由委托的 ReAct 循环，**由 LLM 决定调哪个 `delegate-<skill>` 工具**（它只看得见这 4 个工具，[factory.py:1-11](packages/pi-career-skills/src/pi_career_skills/agents/factory.py#L1-L11)）；但**技能是否真的能跑，由确定性内核验门槛**。模型选路，内核验票。
- **工具链级联依赖**：前置条件链 `none → structured_job_details → job_bearing_artifact` 编码在能力注册表（[capabilities.py:90-155](packages/pi-career-skills/src/pi_career_skills/agents/capabilities.py#L90-L155)），运行时 `_skill_has_evidence` 再验（[controller.py:788](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L788)）。**下游技能不可能在没证据时被委托成功**——依赖被显式编码，不靠提示词自觉（[controller.py:526-546](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L526-L546)）。
- **循环终止条件（防死循环）三重**：
  1. **自然终止**：内层 while 在"无更多工具调用"时退出（[agent_loop.py:174-245](packages/pi-agent-core/src/pi_agent_core/agent_loop.py#L174-L245)）。
  2. **预算硬顶**：agent_turns / tool_calls / input_tokens / wall_clock 全部有架构级硬顶（`HARD_CAPS`，[budgets.py:20-27](packages/pi-career-skills/src/pi_career_skills/runtime/budgets.py#L20-L27)）。
  3. **stall 检测**：没产出 artifact 的调用计数，**6 次软停**（steer 一条中文收尾指令，只提醒一次）、**9 次硬停**（raise `NO_PROGRESS`）（[budgets.py:305-339](packages/pi-career-skills/src/pi_career_skills/runtime/budgets.py#L305-L339)）。
- **反直觉设计（含金量）**：工具配额**随可信证据增长**——每持久化一个 artifact，工具配额 +8（`effective_tool_cap`，[budgets.py:103](packages/pi-career-skills/src/pi_career_skills/runtime/budgets.py#L103)）。**"真的在产出"的 agent 有更多弹药，"原地打转"的 agent 撞硬顶。**这比固定配额聪明得多。

## 第四维度：稳健性与可观测性（工程底座）

**逻辑支点**：解决"如何放心投入生产"。这是 Demo 走向 MVP 的门槛。

### 4.1 状态机管理：状态机有，Checkpointing **没有**

- **有的**：两层状态机——run 级 `RunState/RunStatus/transition`（[runtime/state.py](packages/pi-career-skills/src/pi_career_skills/runtime/state.py)）+ 委托级六态 `DelegationStatus`（SUCCESS/PARTIAL/NEED_USER/RETRYABLE/BLOCKED/FAILED，[contracts.py:13-21](packages/pi-career-skills/src/pi_career_skills/agents/contracts.py#L13-L21)），每态映射一个确定性动作（`DelegationAction`，[contracts.py:34-41](packages/pi-career-skills/src/pi_career_skills/agents/contracts.py#L34-L41)）。
- **如实写：没有 Checkpointing / 中断恢复**。pi-agent-core 的 `Session`/`JsonlSessionStorage` 持久化能力**没有被本项目使用**；controller 无 checkpoint/resume。attempt 之间的预算结转是内存中的（`restore_consumed`，[controller.py:219](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L219)）。**长任务中断后无法恢复，只能重跑**——这是一个明确的工程缺口，面试时可诚实指出。

### 4.2 兜底与护栏：成本熔断和步数封顶是重头戏；内容安全过滤**没有**

- **成本熔断（有，且最强）**：预算三件套挂在 pi-agent-core 的钩子上（`build_controller_hooks`，[agent_hooks.py:52](packages/pi-career-skills/src/pi_career_skills/runtime/agent_hooks.py#L52)）——`stream_fn` 扣 turn+model_request、`should_stop_after_turn` 扣 input tokens + 查墙钟、`before_tool_call` 扣 tool_call。**计费不写在业务工具里，是横切关注点挂钩子**。硬顶在构造时逐项 clamp，调用方传 99999 也没用（[budgets.py:20-27](packages/pi-career-skills/src/pi_career_skills/runtime/budgets.py#L20-L27)）。
- **子代理独立计费桶**：每技能有默认预算（discovery 24/48/32/200k/300s，其余 12/12/16/100k/180s，[capabilities.py:98-104](packages/pi-career-skills/src/pi_career_skills/agents/capabilities.py#L98-L104)），`tracker.child` 开独立桶（[budgets.py:240](packages/pi-career-skills/src/pi_career_skills/runtime/budgets.py#L240)）——子代理烧完自己的就停，不连坐主循环。
- **有界自动恢复**：attempt 失败且错误码可恢复 → 下一次 attempt 预算放宽 1.5x/2.0x，但消耗累计传递、恢复次数有硬顶（[controller.py:166-348](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L166-L348)）。**恢复是策略，不是无限循环。**
- **执行步数封顶（有）**：agent_turns 硬顶 + 动态 tool_calls 配额，双重。
- **如实写：内容安全过滤器（敏感词/有害内容拦截）没有**。只有 `error_message` 脱敏（`redact_message`，[controller.py:38](packages/pi-career-skills/src/pi_career_skills/runtime/controller.py#L38) 导入）。

### 4.3 可观测性：结构化事件流 + 确定性审计闸（有）；Trace 链路 / 看板（**没有**）

- **有的：有界事件流**。`EventLogger` 是内存 append-only 事件日志（seq / type / run_id / attempt_id / 有界 payload，超限截断为 stub，线程安全、可订阅，[events.py:22-84](packages/pi-career-skills/src/pi_career_skills/runtime/events.py#L22-L84)）。关键事件：`tool_observation`（工具名/status/error/promoted 数）、`delegation_{status}`（技能/error_code）、`stall_soft_warning`（[agent_hooks.py:200-241](packages/pi-career-skills/src/pi_career_skills/runtime/agent_hooks.py#L200-L241)）。**订阅者机制**意味着评测端可以把它接进落盘记录。
- **有的：评测审计闸**。evaluation/audit.py 对四个技能各有确定性审计（`_audit_discovery`/`_audit_matching`/`_audit_tailoring`/`_audit_planning`，[audit.py:366](packages/pi-career-skills/src/pi_career_skills/evaluation/audit.py#L366)/[audit.py:433](packages/pi-career-skills/src/pi_career_skills/evaluation/audit.py#L433)/[audit.py:494](packages/pi-career-skills/src/pi_career_skills/evaluation/audit.py#L494)/[audit.py:558](packages/pi-career-skills/src/pi_career_skills/evaluation/audit.py#L558)）——用确定性代码复盘 agent 行为，而不是用人肉看日志。
- **如实写：没有跨调用的 Trace 链路**（无 trace ID 串联每次 LLM 调用与工具返回、无 token/耗时明细看板）。可观测性停留在"结构化事件 + 审计记录"层面，没有到"全链路追踪"。
- 网络治理器额外记录了站点冷却和缓存行为，但目前仍是进程内状态；它不是持久化指标系统。若要生产化，应把域名请求数、缓存命中率、反爬率和冷却次数接入统一 trace/metrics 后端。

## 第五维度：持续进化与评估闭环（反馈飞轮）

**逻辑支点**：解决"如何越用越好"。这是项目的长期生命力。

### 5.1 离线评估集（Golden Dataset）：有，且是项目重心

这是本项目做得最重、最有含金量的一维。`evaluation/` 是一个完整的离线评测闭环：

- **链式评测**：`run_chain` 把多环节串起来（"发现 → 匹配 → 简历 → 计划"），环节 N+1 只在 N 成功时执行（[chain.py:303-306](packages/pi-career-skills/src/pi_career_skills/evaluation/chain.py#L303-L306)）；证据继承两路——`observed_public_evidence`（24KB UTF-8 字节预算，CJK 感知二分裁剪，[chain.py:46-57](packages/pi-career-skills/src/pi_career_skills/evaluation/chain.py#L46-L57)）+ `structured_job_candidates`（≤12 条 / 32KB），经 `seed_artifacts` 走**同一条 add_observation 路径**注入下一环（[chain.py:212-254](packages/pi-career-skills/src/pi_career_skills/evaluation/chain.py#L212-L254)）。
- **确定性审计**：audit.py 四闸（见 4.3）保证评测结论可复现、不被模型话术带偏。
- **结果落盘**：评测记录写 JSON（[runner.py:251](packages/pi-career-skills/src/pi_career_skills/evaluation/runner.py#L251)）、launch manifest 写文件（[cli.py:166](packages/pi-career-skills/src/pi_career_skills/evaluation/cli.py#L166)）、源对比输出 markdown（[compare.py:349](packages/pi-career-skills/src/pi_career_skills/evaluation/compare.py#L349)）——**离线评估 = 自动化回归验证每次 prompt/模型升级是否衰退**，这正是"越用越好"的第一环。
- **回归保障**：当前 pi-career-skills 包 `519` 个测试全绿——faux model + stub registry 的 hermetic 测试把控制器逻辑从随机性里剥离出来（模型用 `FAUX_MODEL`，工具用 `build_stub_registry` 替换真实 handler）。
- **传引用边界已修复**：链式评测现在把候选岗位持久化为 `seed_artifacts`，下一环只接收有界引用/投影，不再把候选岗位原文塞进 goal；URL 也在进入评测前按 canonical identity 去重（[`evaluation/url_utils.py`](packages/pi-career-skills/src/pi_career_skills/evaluation/url_utils.py)）。
- **真实外部限制仍需单独统计**：25 题实测中，反爬应记录为 `waiting_user / anti_bot_challenge`，不能和普通失败混为一谈；最新治理回归目录中 C001、C002 已成功，C003 因外部模型流长时间无输出而人工停止，未计为通过。

### 5.2 在线自进化机制：**没有**

- 无隐式反馈采集（用户采纳/复制/修改行为追踪）：grep `feedback`/`preference` 只命中**求职偏好**（业务输入数据，如"希望城市/薪资区间"），不是用户对结果的反馈信号。
- 无显式打分回写、无优质交互入库、无小模型微调。

**如实写：本项目是"离线评估驱动迭代"，没有在线学习闭环。** 面试时这反而是加分点——诚实说明"进化目前靠离线 golden set 回归，在线反馈是下一个迭代点"，比假装有自进化机制强得多。

## 面试五句话（五维串讲）

1. **范式（第一维）**：ReAct 是标配；差异化在 Trusted Kernel —— 模型输出从不直接信任，证据、预算、完成门是权威。
2. **记忆（第二维）**：没有向量库和上下文压缩，靠"有界投影 + 每委托 fresh agent + 预算"防爆；跨代理共享靠带质检章的 EvidenceStore 黑板书架。
3. **行动（第三维）**：统一 ToolObservation 信封 + 双层技能隔离；模型选技能、内核验前置证据门槛；三重循环终止 + "证据换配额"防死锁。
4. **稳健（第四维）**：预算三件套挂钩子实现成本熔断与步数封顶，子代理独立计费桶，有界自动恢复；但无 checkpoint、无内容安全过滤、无 trace 链路——都如实承认。
5. **进化（第五维）**：离线评测闭环（链式评测 + 确定性审计 + 519 回归测试）是当前引擎；在线反馈自进化没有实现，是明确的下一步。
