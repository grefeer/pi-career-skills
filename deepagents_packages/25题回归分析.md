## 3. 18 题失败机制分类

### 3.1 数据源限制：JS 渲染/封锁源无法产出 jd_complete 证据（14 题）

| 题 | 错误码证据 | 说明 |
|---|---|---|
| C006/C007/C008/C010 | `empty_public_page` → no_progress | iguopin 列表页 fetch 返回空（JS 渲染，静态抓取拿不到内容） |
| Q046 / R024 | browse 成功 ×32/×7 但无 jd_complete | iguopin 浏览器渲染**能拿到列表页卡片**，但无 JD 正文 |
| Q045 | `domain_temporarily_blocked` ×7 | iguopin 临时反爬封锁（harness 按约束不绕过） |
| Q028/Q034 | 空页/搜索失败，仅 1 个 jd_complete | hebut 部分可用，但证据不足以支撑 3 技能链 |
| Q055 | iguopin 仅种子 | career-planning 无输入证据 |
| Q144 | `query-career-sheet-records` ×73 无数据 | 职业表无匹配岗位，预算耗尽 → budget_exhausted |
| R001/R043 | 被杀 ×2 → budget_exhausted | iguopin 仅种子，无证据 |
| R025 | `public_search_failed` ×13 | 搜索 API 持续失败 |

**根因**：iguopin.com 等聚合站列表页是 JS 渲染 SPA，静态 fetch 得空页；浏览器渲染
只能拿到列表卡片（无 JD 正文），详情页被反爬封锁。按常驻安全约束（不绕过验证码/登录/反爬），
这些源无法产出 `jd_complete` 证据 → 硬停滞。**属数据/网络限制，非 harness bug。**

### 3.2 质量门槛：列表页片段不够 jd_complete（2 题）

| 题 | 证据 | 说明 |
|---|---|---|
| C013 | 4 个 promoted 全为列表页片段 | 子代理收集了 40+20 条真实岗位卡片并写成文件，但无 JD 正文 → 质量门槛拒为 job-bearing → completion_evidence_unavailable |
| C014 | 同上 | 子代理自己总结"缺少完整 JD 正文"，停在列表页 |

**根因**：`completion.py` 权威质量门槛要求 `jd_complete`（完整 JD 正文）或 ≥20 字
职责/要求的 `structured_job_details`；列表页卡片（`list_only`）不算。这是 pi 的设计
（VERBATIM from source），保证证据真实可核验。**属数据质量限制。**

### 3.3 搜索 API 持续失败截断链路（1 题）

| 题 | 证据 | 说明 |
|---|---|---|
| Q040 | `public_search_failed` ×12 → no_progress | store 已有 14 个 jd_complete + 3 个结构化详情，但重复失败触发 stall，**resume-tailoring 环节从未被委托** |

**根因**：搜索 API 不稳定（12 连败）触发重复失败守卫截断。**属网络/API 限制。**

### 3.4 resume-tailoring 缺简历事实（1 题）

| 题 | 说明 |
|---|---|
| Q011 | 模型正确识别"需要已确认的简历事实（profile_facts）作为 grounding，评估题未提供"，**拒绝虚构**并请求用户提供简历 → completion_evidence_unavailable |

**这是安全设计的正确行为**（不虚构经历）。**属评估题欠规格**（resume-tailoring 题未携带候选简历），非 harness bug。

### 3.5 链内技能门禁失败（不影响链 PASS，记录备查）

| 位置 | 证据 | 说明 |
|---|---|---|
| C002[1] resume-tailoring | `target_role_mismatch` ×2 | 子代理从 33 个产物中选错目标 JD（非 AI 应用岗），门禁正确拦截 |
| C003[2] career-planning | `focus_keywords_not_found` ×2 | 子代理传入的关键词不匹配所选 JD 文本，门禁正确拦截 |

属子代理对技能门禁的模型能力不足（选目标/关键词不精确），链因前序链接成功仍为 PASS。

### 3.6 次级发现：成功但无产物的查询不触发 stall

`query-career-sheet-records` 等工具"成功但无产物"时不会累积 stall 警告（只有失败/重复
才计），子代理可烧光 40 次模型调用预算（Q144 达 73 次查询）。有界收敛（模型调用上限 +
修复 4b 兜底），不再无限循环，但属效率缺口，可作为后续优化项。

## 4. 结论

- **harness 缺陷（机制 1-4）已全部修复并经真实 API 验证**：ls 循环、matching 盲回退、
  完成契约证据门槛、被杀委托无限循环 + 超时跳过 store 判定。其中 C002 从 2400s 失败
  变为 194s 成功是最强证据。
- **剩余 18 题失败全部为数据源/网络/模型能力限制，不是 harness bug**：
  - iguopin 等 JS 渲染源无法产出完整 JD 证据（14 题）
  - 列表页片段达不到 jd_complete 质量门槛（2 题）
  - 搜索 API 不稳定（1 题）
  - resume-tailoring 评估题缺简历事实（1 题，正确拒绝）
- **安全约束全程未被突破**：`domain_temporarily_blocked`/验证码/登录等一律按约束返回
  失败并收敛为 waiting_user，未尝试任何绕过。
